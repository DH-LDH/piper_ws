# 펌웨어 1.9-1 업데이트에 따른 코드 변경 범위 조사 (2026-11-11)

조사만 했고 코드는 바꾸지 않았다. 대상은 S-V1.7-3 → S-V1.9-1 업데이트 뒤 우리 코드가 돌아가려면 바꿔야 할 곳이다.

**결론: 코드 변경은 작다. 네 파일에서 약 10줄이다. 시간이 드는 쪽은 코드가 아니라 업데이트 뒤 실기에서 다시 확인해야 하는 동작(4절)이다.**

## 1. 현재 상태

| 항목 | 값 | 확인 방법 |
|---|---|---|
| 하드웨어 | V1 | ArmRobotUA Upgrade 탭 (11-11) |
| 관절 노드 1–6, 그리퍼 노드 7 | H-V1.2.0 / V1.0.7 | 같음 |

0.7.0a1은 시험용 프리릴리스이고 PyPI에는 없다(PyPI 최신은 0.6.2). GitHub에서 설치해야 한다.

## 2. SDK V2와 V3의 차이 (우리가 쓰는 범위)

`C_PiperInterface_V3`는 `C_PiperInterface_V2`를 상속하고 일부만 덮어쓴다. 우리가 쓰는 메서드 19개를 0.6.2의 V2, 0.7.0a1의 V2, V3 세 곳에서 대조했다.

### 2.1 바뀌는 것

| 항목 | V2 (지금) | V3 (1.9-1) | 근거 |
|---|---|---|---|
| MIT 진입 `MotionCtrl_2`의 `move_mode` | `0x04` | **`0x06`** | V3 `MotionCtrl_2` 설명 "0x06: MOVE M, supported since V1.8-8", V3 데모 `MotionCtrl_2(0x01, 0x06, 0, 0xAD)` |
| 상태 피드백 `mode_feed`의 MIT 값 | `0x04` | **`0x06`** | 0.7.0a1 변경 이력 |
| MIT 토크 필드 | 8비트, ±8 N·m, 한 칸 16/255 = 0.0627 | **12비트, ±16 N·m, 한 칸 32/4095 = 0.0078** | `_JointMitCtrl`의 `FloatToUint(t_ref, t_min, t_max, 12)`, `t_min=-16.0, t_max=16.0` |
| MIT 프레임 마지막 2바이트 | kd 하위 4비트 + 토크 8비트 + CRC 4비트 | kd 하위 4비트 + 토크 12비트 (CRC 없음) | `protocol_v3` 인코더 |
| `JointMitCtrl` 입력 검사 | 없음 | NaN·Inf 거부, 범위 밖이면 경고 후 클램프 | V3 `_JointMitCtrl` |
| `installation_pos` | 0–3 | 0–4 (수평 뒤집힘 추가) | V3 `MotionCtrl_2` |

토크 한 칸이 8배 촘촘해진다. 손목 관절에서 토크 해상도 때문에 발진하던 문제(10-20)에 유리한 변화다.

### 2.2 그대로인 것

- **호출 형태**: 19개 메서드의 인자 목록은 0.6.2 V2와 0.7.0a1 V2가 모두 같다. V3가 덮어쓰는 것은 `GetArmStatus`, `MotionCtrl_2`, `GripperCtrl`, `JointMitCtrl` 네 개이고 인자 이름과 순서는 같다.
- **위치 모드 값**: MOVE P `0x00`, MOVE J `0x01`, MOVE L `0x02`, MOVE C `0x03`은 그대로다.
- **MIT 플래그**: `is_mit_mode=0xAD`는 그대로다.
- **MIT 필드 범위**: 위치 ±12.5 rad(16비트), 속도 ±45(12비트), kp 0–500(12비트), kd ±5(12비트)는 그대로다.
- **CAN ID**: 기존 ID는 변함없고, IK 관절 피드백 0x2AA–0x2AC만 추가됐다.
- **그리퍼**: V3의 `GripperCtrl`은 기존 폭 모드(0.001 mm, 0.001 N·m)를 유지한다. 각도 모드는 별도 `GripperCtrl_V3`다.

### 3.5 권장하는 방식

네 파일이 각자 클래스를 고르지 않게, 인터페이스를 만들어 주는 작은 공용 함수를 하나 두는 것을 권한다. 펌웨어 버전 문자열을 읽어 V1.8-8 이상이면 V3와 `0x06`·12비트 값을, 아니면 V2와 `0x04`·8비트 값을 돌려주는 식이다. 이렇게 하면 업데이트 전에 코드를 미리 넣어 두고 기존 펌웨어에서 그대로 시험할 수 있다. 0.7.0a1에도 V2가 들어 있고 호출 형태가 같으므로, SDK를 먼저 올려도 기존 펌웨어 동작은 유지될 것으로 보인다. 다만 실기로 확인한 것은 아니다.

## 4. 업데이트 뒤 실기에서 다시 확인할 것

코드로는 알 수 없고 재 봐야 하는 것이다. 시간은 여기에 든다.

| # | 확인할 것 | 왜 |
|---|---|---|
| 1 | 관절별 MIT 토크 계수 | S-V1.7-3에서는 [0.25×3, 1.25×3]이었다. 1.9-1에서도 같은지 모른다. 틀리면 중력 보상과 TDE 관성 추정이 전부 어긋난다 |
| 2 | 실제 토크 상한 | 프로토콜은 ±16이지만 펌웨어가 더 낮게 자를 수 있다. J2 클립(−4.0) 기준과 부하 상한 0.3 kg의 근거가 여기에 걸려 있다 |
| 3 | Kp·Kd 스케일 | 위고 글: "Kp/Kd 스케일은 펌웨어 버전별로 다릅니다". 지금 쓰는 Kp 10, Kd 0.8이 같은 강성인지 확인 |
| 4 | MIT 진입·종료 동작 | 진입 시 튐, 종료 뒤 대기 모드로 가는 문제가 그대로인지 |
| 5 | 0° 쪽 순간 튐 | 위고에 문의한 현상. 없어졌는지 30 s 정지 시험으로 확인 |
| 6 | 토크 피드백(effort) 스케일 | 보낸 토크와 읽은 토크의 대조(`MISMATCH_NM`)에 쓰인다 |
| 7 | 영점 | 영점 학습 뒤 관절 0점이 달라질 수 있다. 자세 A·B 재현, FK 대조, eye-in-hand 보정 확인 |
| 8 | 속도 | "회전 속도가 감소"했다고 공지됨. 위치 모드 추종 지연(67–83 ms)이 그대로인지 |
| 9 | 구조 모드 | 약 7 Hz(자세 A), 6 Hz(자세 B)와 감쇠비. 주파수는 구조 특성이라 유지될 것으로 보이나, 속도루프 게인이 바뀌어 감쇠는 달라질 수 있다 |
| 10 | 전원 투입 자세 | V1 + V1.8-2 이상은 영점 자세에서 전원을 켜야 한다. 실험 절차에 반영 |

1–3번이 끝나야 기존 제어기(①·②·④-off)를 새 펌웨어에서 재현할 수 있다.

## 5. 남은 질문

- 1.9-1에서 piper_sdk 0.7.0a1과 pyAgxArm 중 무엇을 권장하는지 (위고 문의 중)
- 4절 1–3번 값을 위고나 AgileX가 문서로 갖고 있는지. 있으면 측정을 줄일 수 있다
- 업데이트 뒤 영점 학습이 1.9-1에도 필요한지와 절차 (위고 문의 중)
