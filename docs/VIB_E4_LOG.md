## 검증 (8절 10/26 오후)

- "4–16 Hz 대역통과는 기하 중심 8 Hz에서 위상이 거의 0" — **확인.** 구현한 이산 필터 위상은 100 Hz에서 6 Hz +11.4°, 7 Hz +5.4°, **8 Hz +0.4°**, 9 Hz −3.8°, 10 Hz −7.2°.
- "8 Hz에서 10 ms = 29°" — **확인**(360 × 8 × 0.01 = 28.8°).
- "k ≈ 0.2 → 0.5 → 1.0 (k·|H| 0.1 → 0.25 → 0.5)" — 계산은 맞음. 참고로 양자화 때문에, 센 툭에서 v ≈ 0.3–0.6 rad/s일 때 k = 0.2이면 τ_vib가 0.06–0.12 N·m(1–2칸)이다. v가 0.16 rad/s 밑으로 내려가면 반 칸(0.031) 아래가 되어 사실상 0이 된다. k = 0.2 단계는 툭 직후 몇 주기에만 작동한다는 예상치다(오류 아님).
- "재시행 창 1.5 s: ζ 0.05, 8 Hz에서 1/e 시간 약 0.4 s" — **확인**(1/(0.05 × 2π × 8) = 0.40 s).
- "기울기 게이트 35.0°" — 반영. F2(MIT 시작 35.03°)는 문턱에 0.03° 차이로 걸치므로, 경계에 걸리는 회가 나올 수 있다.
- "Td = IMU 장치 시각 → τ_vib CAN 송신" — 반영. 다만 장치 시각을 PC 시계로 바꾸는 오프셋이 "가장 빨리 온 표본의 수신 − 장치 시각"이라, USB 최소 전달 시간과 CAN 송신 뒤 모터 반영 시간은 들어가지 않는다. 그래서 잰 값은 **하한**이다.

## 4. 8절 10/26 저녁 반영 — 시각 정렬·튐 거부·조화 예측 (가짜 팔, 10-26 14시)

**코드** (`vib_damp.py` 다시 씀, `imu_stream.gyro_after`, `mit_probe`, `vib_probe --resume`, 새 `tools/vib_tap_report.py`):
- v는 **자이로 표본마다 그 표본 시각 t_g의 q̇**(엔코더 이력 40주기, 선형 보간)로 계산하고, 대역통과도 새 표본이 올 때만 h = 표본 간격으로 갱신한다. 제어 주기마다 같은 표본을 다시 넣지 않는다.
- 엔코더 튐 거부: 한 주기 |Δq̇| > 0.5 rad/s인 관절이 표본 시각에 걸리면, 원값과 직전 정상값 중 **자이로 피치를 더 잘 설명하는 쪽**을 쓴다. 엔코더만 튀었으면 직전값을 쓰고, 실제 툭 운동이면 자이로가 따라가니 원값이 남는다. 거부 횟수는 `.vib.csv` rejects에 기록한다.

- "v/τ_sent는 k와 무관한 개루프 H" — **확인.** 단, 처프 위상에 고정한 lock-in 비(간접법)로 구해야 폐루프 잡음 편향이 없다. 그렇게 구현했다.

## 18. (가) 첫 실기(163243) — 약한 상태라 게이트 불통과(k 0 전 구간), 실기에서 드러난 버그 두 개 고침 (10-27 16:32)

복구(32.66°, 33° 무리) → dry-run → `mit_probe … --plan "sine:2,id:18,ck:0.2:18,ck:0.5:18,ck:1.0:18,onoff:6,id:18" --go`(125 s, 정상 종료, 도메인 전환은 MIT 3.4–3.7 s 전).

`vib_plan_report` 형식:
- 식별(구간 1): H 피크 **0.266** 잔차 28° 설명력 0.91 절반 ψ −85/−83° → ψ −88° f₀ 7.75 Hz ζ 0.06 | **게이트 불통과(H < 0.5)**
- ck 0.2·0.5·1.0: 안 켬 / on/off: k_ok 0 → 짝 없음(기준선 a′)
- 재식별(구간 6): H 0.206 잔차 25° 설명력 0.85 ψ −96° → **Δψ −7°**(시행 안 상태 유지)
- 기울기(유지 자세): 첫 식별 32.75° | 끝 32.57°
- 33° 무리는 지금까지도 H 0.21–0.38(약함)이라 예상대로. 식별 자체는 깨끗(절반 ψ 차 2°, 설명력 0.85–0.91) — 실시간 식별·게이트가 실기에서 동작함을 확인.

**실기에서 드러난 버그와 수정**
1. **루프 멈춤이 시간에 따라 늘어남**(구간별 0·1·7·11·7·20·23회, 최대 78 ms, 전체 31회): `imu_stream` 콜백이 20표본마다 누적 오프셋 배열(최대 60000개) 전체의 중앙값·하위 1%를 **락을 잡은 채** 계산 → 표본이 쌓일수록 락 시간이 늘고 제어 루프의 `gyro_after`가 기다림. 44 s 시행에선 2–5회라 안 보였음. 고침: 미리 잡은 고리 배열, 1 s마다 복사만 락 안에서, 계산(O(n) partition)은 락 밖, 도메인 전환 중 계산이면 버림. 합성 시험(표본 40000개 ≈ 150 s): 락 점유 최대 **13.05 → 0.05 ms**, 오프셋 정확도 그대로(0.0051 vs 참 0.005 s).
2. **엔코더 튐 후보가 영영 끼임**(거부 719회, on/off 구간 503): `vib_damp`가 튐 꼬리 값(J5 −2.5 → +1.6 → +1.8 → **+0.56**)을 정상값으로 받아들인 뒤, 0 근처 실제 J5 속도가 늘 0.5 넘게 달라 그 뒤 모든 주기가 후보 → 표본마다 "자이로를 더 잘 설명하는 쪽"을 골라 **실시간 v를 체계적으로 줄임**. 지난 회 영향: 대부분 후보 주기 ≤ 2%, 145621 8.3%(주로 앞 절반)·145101 5.6%, 이 회 51%. 고침: 같은 관절 후보가 4주기(약 40 ms) 넘게 이어지면 지금 값을 정상으로(실제 튐은 1–3주기). 재생 확인: 163243 51 → 0.5%, 145621 8.3 → 1.1%, 145101 5.6 → 0.7%, 143718 0.5%.
3. (작은 것) 계획 모드의 "MIT 시작" 기울기·실시간 기울기 기록이 a′ 도중(38.4°, 다른 자세)이었음 → 첫 유지(식별) 구간 0.3–1.8 s로 옮김. `vib_plan_report`도 같은 창.

- 145621의 앞 절반 맞춤 실패(6.5 Hz bin 튐)와 시행 안 ∠H 60° 이동 일부가 2번 버그 탓이었을 수 있다(그 회 앞 절반 후보 비율 높음). 다른 회는 영향 작음.
